# 本実装の仕様と検証範囲

2026-09-19。会話で合意した初期版の要件を実装へ対応付けた記録です。

## 要件との対応

| 要件                                     | 実装                                                                                                                                                           |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| シングル対戦、手動入力、途中入力でも計算 | 相手の6枠が空でも対面計算可能                                                                                                                                  |
| ダメージ幅・HP割合・一撃撃破率・攻守交換 | Champions（gen 0）、SPを直接入力。乱数16通りを同確率で集計し、重複するダメージ値も確率に加算。結果カードが画面外なら固定サマリーに同条件での反復撃破目安も表示 |
| すばやさ・行動順                         | 専用ページの速度帯比較と、対面の優先度／トリックルーム判定                                                                                                     |
| 3パーティ×6体、攻守の履歴6件             | 既存保存形式v1を維持。技セットを固定4技から編集可能に拡張                                                                                                      |
| 判明情報と仮定の区別                     | 判明チェックと判明技を明示。相手切替時に判明した型の値を復元                                                                                                   |
| 相手の複数の型を比較                     | 採用上位の独立項目、速度、物理耐久、スカーフ。判明項目は仮定で上書きしない                                                                                     |
| 技＋交代の上位3候補、根拠を表示          | 決定的なルール評価。入力済みの控えを評価し、条件を満たす場合は交代先不明の候補も示す                                                                           |
| 日次更新、通信失敗時の前回値、手動再試行 | 日本時間の初回利用／フォーカス復帰／次の入力で日付を確認。失敗の自動再試行は翌日、手動は随時                                                                   |
| データ日付と取得時刻を区別               | API内の日付と通信成功時刻を別々に表示                                                                                                                          |
| 端末内保存、ファイル移行、ログイン不要   | localStorageとJSON移行。書込み成功後にだけ完了通知し、失敗時はエラーを表示                                                                                     |
| PC・スマートフォンで常用                 | レスポンシブUI。HTTPS公開は未実施。静的配信できる成果物を生成                                                                                                  |

バトル画面の結果は入力に応じて自動更新します。「結果を見る」は結果への移動のみで、履歴保存は別操作です。履歴には攻守の型（ポケモン・性格・配分・持ち物・特性・技）を記録し、HPや天候などの条件は含みません。

パーティごとに編集状態を表示します。変更のある全パーティを検証して保存後に書き出し、保存失敗時も編集を保ってバックアップを書き出せます。「保存済みを書き出す」は保存済みデータだけを含みます。

見せ合い枠は共有検索Pickerで名前・図鑑番号を検索し、他枠の選択を除外します。同じポケモンを選び直すと選出・ひんし状態を維持し、別のポケモンへ変更すると未確定に戻ります。スマートフォンでも攻守カードは幅320px以上で横並びにします。

## 計算の前提

- 持ち物の候補は種族・フォームで絞ります。メガストーンは対応する通常フォーム、でんきだまはピカチュウ、ながねぎはカモネギ系統に限定します。専用効果の対応は [Showdownの持ち物定義](https://github.com/smogon/pokemon-showdown/blob/master/data/items.ts) に基づきます。技・特性・天候などで発動条件が変わる一般の持ち物は候補に残します。メガフォームを直接選んだ場合は、従来の計算仕様に合わせて「もちものなし」のみ選べます。
- 保存済みの対象外の持ち物は削除・自動変更せず、選択不可の現在値と選び直しの案内を表示します。過去のバックアップは引き続き読み込めます。採用データからの型提案にも同じ候補制限を適用します。
- 持ち物はそのポケモンのシングル採用率の高い順に表示し、候補名に採用率を併記します。割合が欠落している場合は提供元の採用順位順を使用します。「もちものなし」は常に先頭、統計にない候補は末尾の五十音順です。未取得・対象違い・未対応シーズンでは全候補を五十音順にし、並び順の理由と利用したデータ日付を表示します。並び替えで選択中の持ち物は変えません。
- `@smogon/calc` は **0.12.0** に固定し、**Generations.get(0)** を使用。レベルや個体値は入力させず、Championsモードで処理します。
- 通常HPは種族値＋SP＋75、その他は性格補正前に種族値＋SP＋20。SPは各0〜32、合計66以下。端数処理はライブラリに従います。
- HP%入力は最大HPから切り捨てて実HPへ変換。ダメージ割合は最大HP比、一撃撃破率は現在HPに対して算出します。
- 連続技は指定回数がすべて命中した条件で各ヒットの乱数分布を合成。命中回数そのものの確率は混ぜません。
- 満タンのタスキ・がんじょうは最初のヒットの致死ダメージを抑制。連続技の後続ヒットでは倒せます。
- かるわざ発動中は道具を失った条件として扱います。対応するメガストーンを持たせた型は、メガシンカ済みとして種族値・タイプ・特性・ダメージ・行動順を計算します（X・Y・Zを区別）。すばやさ専用ページへの読み込みも同じフォームを使用します。進化前の種族と特性は保存した型に保持し、石を外すと元に戻ります。メガ中の特性欄は自動設定で固定します。計算ライブラリにも対応するメガストーンを渡し、他の持ち物補正とは併用しません。メガフォームを直接選択する従来の操作にも対応します。
- 全358フォームで全身イラストを使用します。選択・対戦・パーティ・履歴・すばやさ一覧の画像を統一し、ドット絵への切替を廃止しました。ミミッキュのばれたすがたのみ別シリーズの公式イラストです。画像の出典・取得記録は [artwork-sources.md](artwork-sources.md) に記載しています。
- 技の優先度、いたずらごころ／はやてのつばさ／ヒーリングシフト、後攻の道具・特性、まひ、おいかぜ、天候特性、トリックルームを行動順へ反映。確率発動の先制効果は「未確定」とします。
- 天候は場の入力値を使用します。ひでり・あめふらし等による入場時の天候変更は自動入力しません。いかく等の条件付き効果は詳細欄の「条件付き特性が発動中」で指定し、ランクとの二重指定に注意してください。

## 行動候補の評価

相手の想定型からのダメージ、一撃可否、先手、交代技、回復需要などの有効性を評価し、未判明技は採用率で重み付けします。技の1位候補は採用率20%以上、または判明済みの技に限定します。割合がない場合は採用順位上位4技を対象とし、順位の逆数で重み付けします。判明済みの技は所持が確認されているため、低採用率でも1位になり得ます。低採用率の未判明技しか評価できない場合は、無理に1位を提示せず不足情報を案内します。点数は内部の順位付けだけに使い、行動の選択確率として表示しません。

名前付きの交代先はユーザーが入力した個体に限定し、選択したこちらの技を受けた場合に有利になる候補を評価します。相手6種族・選出3体のどちらもまだ全て判明していない場合、現在HPの半分以上を失う可能性がある対面や、ねむり・こおりで行動しにくい状況では「交代（交代先は不明）」も候補にします。未知の種族・型・相性を作り出さず、安全に受けられるとは限らないことを明記します。

控えの型を入力済みの場合、判明フラグのある特性・もちもの・性格・配分を交代候補へ反映します。未判明項目は標準値で補います。能力変化技は対象と増減を区別し、候補の使用者に有利な変化だけを加点します。シングルで対象となる味方がいない技は候補から除外します。

統計の技・特性・性格・持ち物・配分は独立した頻度です。それらを組み合わせた型を「実際に何%使われる型」とは扱いません。上位候補のダメージ評価は採用上位（取得できない場合は入力値）の一つの仮定を使い、他の型は比較欄で確認します。

判明4技以外の技、習得できない技、無効な攻撃、満タン時の単純回復、ひんしの交代先などを除外します。ねむりは継続を仮定し、こおり解除は推測しません。一部の明確な状態異常無効も除外します。

## 統計の取得・保存

- 提供元は、要件整理で選んだ非公式の [Pokémon Champions Battle Data API](https://championsbattledata.com/api_guide)。[利用ルール](https://championsbattledata.com/api-rules/)に従い画面で帰属を表示します。
- 一覧 `/api` を1日1回確認。個別は攻撃側・受け側と表示中のパーティの編集対象について `/api/battle/Singles/{id}?days=1` を取得・キャッシュします。持ち物の採用率表示と既存の行動候補は同じキャッシュ・同時通信の重複抑制を使います。全個体の詳細を一括巡回しません。
- JSONの形式・個体ID・Singles・日付・採用率・SP配分を検証。不正データで前回値を置き換えません。端末キャッシュも読み込み時に検証します。
- 攻撃側・受け側やパーティの新規／入替枠でポケモンを選ぶと、個別データと最新シーズン一覧の確認後に合法な採用上位を初期型へ適用します。特性・持ち物・性格・配分・技はカテゴリごとの統計から独立して選ぶため、その組み合わせを実際に使われた一つの型とは扱いません。割合が揃うカテゴリは採用率順、揃わないカテゴリは提供元の順位順です。習得可能な採用上位技が4つ未満なら取得できた技だけを設定し、残りの枠は空欄のまま編集できます。各カテゴリに合法な候補がない場合は通常の初期型を維持します。
- メガフォームを直接選択した場合は、`itemCatalog.megaStone`の通常フォーム名→メガフォーム名が一意に対応する場合だけ、対応する通常フォームの採用統計を取得します。X/Y/Zなど別フォームの統計IDから推測せず、採用データ欄と初期型の通知に統計元の通常フォーム名を表示します。統計項目は選択したメガ後フォームの特性・「もちものなし」・習得技・性格・能力ポイント制限で再検証し、無効な候補は飛ばします。通常フォームの使用順位からメガフォームを逆推定しません。対応先がない、最新シーズンが未対応、または有効な統計がない場合は通常の初期型を設定し、画面で理由を知らせて編集可能にします。通信に失敗しても検証済みの前回キャッシュがあれば適用し、更新エラーを通知します。
- 選択中の画面は取得完了まで開いたままで、別のポケモン選択やキャンセルができます。古い要求の結果は適用しません。履歴・保存済み型を選んだ場合は内容をそのまま復元し、相手の判明済み項目は再選択後も維持します。
- 同一タブ内の同時要求をまとめ、15秒でタイムアウト。失敗時も当日の試行を記録し、自動ループを避けます。手動再試行は常に可能です。
- 一覧が使用順位だけを提供する場合、順位を使用率%に変換しません。統計にない割合は「割合なし」と表示します。
- 保存は各個体の最新スナップショットのみ。履歴アーカイブやAPIのミラーは作りません。保存領域が使えない場合はメモリー内で保持し、画面に通知します。
- パーティと履歴は端末へ書き込めた後にだけ成功通知を表示します。JSON化や`localStorage`への書込みに失敗した場合は成功通知を出さず、ページ内警告と通知でバックアップを案内します。保存失敗時の既存値維持と次回書込みでの回復をStorage doubleで検証しています。
- カタログの対応シーズンは **M6**。一覧または個別データが未検証シーズンなら自動予測を停止し、統計の型への自動適用も停止します。手動の計算は引き続き可能です。
- 相手を選ぶ際、その公開種族IDが提供元へのURLに含まれます。型、パーティ、HP、判明情報などは送信しません。

## 制約・残る作業

- ライブラリが扱うダメージ計算を中心にした初期版です。対戦全体の再現ではありません。命中、急所発生確率、ひるみ、行動不能、技の追加効果、設置技、回復アイテム以外のターン終了時の回復・定数ダメージを含みません。
- きあいのハチマキの生存判定も未計算のため、一撃判定を保留します。
- ばけのかわが残っている場合は直接ダメージの参考値と警告を表示し、一撃判定を保留します。解除後は「ばれたすがた」で計算します。
- 名前付きの交代先は満タン、設置技のダメージは未考慮です。控えで判明済みの特性・もちもの・性格・配分は反映し、未判明項目は標準値を仮定します。こだわりによる技固定やアンコール／かなしばり、みがわり、変身、味方からの効果などの継続盤面は未実装。変化技の成功条件をすべて再現するものではありません。
- すばやさ専用ページは従来の速度比較の対象範囲を維持。対面の状態異常・場の設定は自動引継ぎしないため、実際の行動順はダメージ画面で確認します。
- 対象種族・習得技は静的スナップショットです。日次更新するのは採用統計で、新規種族や仕様変更はカタログ再生成・検証・再公開が必要です。持ち物名はすべて日本語表記です。PokeAPIに未収録の名称は `src/localization/items.ja.json` の確認済み補完データを使い、翻訳漏れがあれば生成処理を停止します。旧英語名の保存データ・バックアップは読み込み時に日本語へ変換します。
- 現在の使用可能一覧と個別イベントの規制が常に一致する保証はありません。新シーズンではカタログと計算仕様を確認してから対応シーズンを更新してください。
- 本番JSは約1.37MB（gzip約303KB）で、ビルド時にチャンクサイズ警告が出ます。コード分割による初回読込の最適化は今後の改善点です。
- HTTPS公開はこの変更では行っていません。公開先の確定と実環境での通信・保存テストが必要です。

## 公開用の準備

`npm ci` → `npm test` → `npm run format:check` → `npm run build` で検証後、`dist/` を静的HTTPSホストへ配置します。サーバー処理、DB、APIキーは不要です。APIへのCORS通信を許可する配信設定が必要です。合意済みの候補はCloudflare Pagesですが、アカウント・プロジェクトの作成や公開は未実施です。

保存領域はオリジン単位です。localhostから公開URLへ移行する際は、旧画面でバックアップを書き出し、新画面で読み込んでください。ブラウザのデータ消去でも保存内容は失われます。

## 日本語表示名の検証

全358フォームが参照する特性・もちもの・技、およびカタログ全体（特性216件、もちもの166件、技525件＋計算用「わざなし」）の表示名を日本語で保持する。英語名は計算ライブラリ・採用データとの照合用に分離する。

PokeAPIに未収録の特性3件は `src/localization/abilities.ja.json` の出典付き補完データで対応する。生成時に翻訳漏れがあればカタログの更新を停止する。日本語名称に英字を含む「ＤＤラリアット」は正規の表記として扱う。

パーティ・攻守の履歴・JSONバックアップの読み込みでは、従来の英語の特性・技・もちもの名を日本語へ変換してから検証する。知らない名称、習得不可の技、重複技、不正な配分を変換によって許可しない。日本語表示名から計算用英語名への対応、全フォームの保存移行を自動テストする。

## 能力ポイントの入力

攻守・パーティ編集・すばやさ比較の数値欄は共通コンポーネントを使用する。半角数字と日本語IMEで入力した全角数字に対応し、変換中は値を確定しない。確定時に先頭の0を除去し、各能力32・合計66の上限へ丸める。入力中は空欄を許可し、フォーカスを外すと0を表示する。フォーカス時に全選択し、上下キーで1ずつ変更できる。数字以外や小数・指数表記は採用しない。

## 回復アイテムと型比較の表示

- 技自体のダメージ（相手の最大HP比）と、回復を含む攻撃後の残りHPを分けて表示します。「回復なし」はアイテムのHP回復だけを除外し、持ち物によるダメージ補正は維持します。切替は型比較欄にも共通で適用します。
- 現カタログの被攻撃側HP回復アイテムであるオボンのみ・オレンのみ・たべのこしに対応。きのみは生存中かつHP半分以下で発動し、連続技では各ヒット後に1回だけ消費します。たべのこしは攻撃後に生存していればターン終了時1回分だけ計算します。かいがらのすずは持ち主が攻撃した時の効果のため、被ダメージからは回復しません。
- 各乱数経路で残りHP・消費状態を保持して回復量と一撃撃破率を計算します。倒れた後は回復せず、最大HPを超えません。入力時点ではアイテムを保持している前提で、過去ターンの消費・発動を推測しません。バトル画面の固定サマリーでは、同じ技を同じダメージ条件で最大10回使う場合の撃破目安も表示します。技ごとに乱数を引き直し、きのみの消費は引き継ぎ、たべのこしは生存した各回の終了時に1回だけ反映します。撃破までの回数は最短回数から確定回数までで示し、最短回数時点の累積KO率を併記します。10回以内に倒せない場合はその範囲で未撃破と表示し、未対応条件では判定を保留します。この目安は威力変化・アイテム除去後のダメージ再計算、能力変化、天候等の推移、相手の行動を含みません。
- はたきおとす等のアイテム除去を反映。ねんちゃく、きんちょうかん、ぶきよう、じゅくせい、ほおぶくろ、サイコノイズの回復封じも判定します。継続中の回復封じなど入力できない過去の状況は「回復なし」で指定してください。未対応の防御効果がある場合は残りHPも判定保留にします。
- 型比較欄のダメージには攻撃方向と使用技、最大HP比であることを明記。性格・もちもの・特性を淡色のラベル付き枠で表示し、能力配分は性格上昇を赤系＋↑、下降を青系＋↓で示します。
- 判定の参照元：[Showdownのアイテム定義](https://github.com/smogon/pokemon-showdown/blob/master/data/items.ts)、[Championsの差分](https://github.com/smogon/pokemon-showdown/blob/master/data/mods/champions/items.ts)、[技定義](https://github.com/smogon/pokemon-showdown/blob/master/data/moves.ts)、[回復量の端数処理](https://github.com/smogon/pokemon-showdown/blob/master/sim/battle.ts)。

## 固定ダメージサマリー

バトル計算ページのみ、主結果カードが画面の表示範囲から外れている間、画面下部に3項目（技のダメージ割合、撃破の目安、回数内のKO率）を固定表示します。結果カードが表示範囲に入ると隠し、離れると再表示します。回復モードを含む現在の入力から計算し、結果カードと同じ計算結果を使います。撃破目安は同じ技・同じ条件を最大10回繰り返す前提です。確定回数まで出せない場合は最短回数と上限内の状態を分けて表示します。変化技、無効攻撃、判定できない防御効果、10回を超える条件を誤って確定撃破と表示しません。

## 対戦画面の入力配置

バトルの条件直下の「パーティから選ぶ」は、攻撃側・受け側を切り替えてからメンバーを選べます。初期の呼び出し先は攻撃側です。受け側への呼び出しは攻撃側と使用技を維持し、相手の使用技を読み込んだ型の先頭技に切り替えます。保存済みパーティは変更しません。

能力ランクは攻撃側・受け側それぞれのポケモン枠内に表示します。ポケモン枠の直下に「場の状態」を独立配置し、両側の条件付き特性・おいかぜ・壁・まもると、共通のじゅうりょくを設定できます。

各ポケモン枠内に「使用するわざ」と開閉式の「わざセットを編集」を配置しています。攻撃側の技は4技から選び、受け側の技選択はすばやさ比較と同期します。開閉式の「HP・状態異常」には両側のHP・状態異常、急所、連続技の命中回数をまとめています。HP入力は受け側のHPスライダーと同期し、ランク・場の状態は攻守の交換とリセットに連動します。

## パーティ保存時のもちもの重複チェック

「パーティを保存」を押した際、編集中のパーティ内で同じもちものを複数のポケモンが持っていれば保存を停止し、もちもの名・枠番号・ポケモン名を警告表示します。空き枠と「もちものなし」は重複に含めません。重複を解消すると警告は消え、改めて保存できます。

編集中の入力はそのまま残し、保存済みパーティを上書きしません。他パーティとのもちもの重複は許可します。従来の保存データ・バックアップの読み込みは維持し、重複が残るパーティを再保存する際に同じチェックを適用します。
