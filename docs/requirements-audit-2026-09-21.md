## 修正対象

### A-01：交代候補に、控えの判明済みの型を反映しない（優先度：高）

**関係する要件：判明情報は仮定で上書きしない／技と交代の候補を根拠付きで表示。**

受け側として一度入力した型と判明フラグは `src/App.tsx:695` 以降で保持するが、予測に渡すのは現在の受け側の `known` と、控えのID・選出状態だけ（`src/App.tsx:1288`）。交代先の評価では `src/predictions.ts:347` の `makeBuild(slot.id)` と `defaultSide()` で型を作り直す。過去に判明した持ち物、性格、配分等を参照できない。

再現例：

1. 通常フォームのギャラドスに「ギャラドスナイト」を設定し、もちもの判明として扱う。
2. 別のポケモンを受け側にし、見せ合い欄にはギャラドスを選出済みとして残す。
3. こちらのガブリアスの「じしん」に対する交代候補を評価する。

ソースの接続関係を確認し、予測関数への控えID 130の入力で「0.0〜0.0%／選択した技を無効化できる」を再現した。同じ計算関数にメガストーン付きの型を渡すと **81〜96ダメージ、47.1〜55.8%** になり、候補の根拠が変わる。

`docs/implementation.md` に交代先は初期配分等の仮定と明記されているため、隠れた仕様ではない。ただし、既に入力済みの確定情報まで使用しない点は、判明情報尊重の要件を部分的にしか満たしていない。

修正方針：控えごとの観測済み型・判明情報を予測に渡し、判明した項目を固定する。未判明項目のみ標準値で補う。回帰テストは「控えに戻った、メガストーン判明済みの相手」を含める。

### A-02：能力を下げる技を「能力を上げる変化技」と評価する（優先度：中）

**関係する要件：行動候補の根拠を正しく示す。**

`generate-battle-catalog.mjs` は、技に `boosts` があるかだけを `boost` に変換する。上昇・下降と、自分・相手の区別を保存しない。`src/predictions.ts:320` はその値を使って14点加算し、「能力を上げる変化技」と説明する。

現在のカタログと `predictActions` を使い、以下を再現した：

| 相手       | 判明技     | 実際に返った説明   |
| ---------- | ---------- | ------------------ |
| フシギバナ | あまえる   | 能力を上げる変化技 |
| フシギバナ | こわいかお | 能力を上げる変化技 |
| スピアー   | いやなおと | 能力を上げる変化技 |

文章だけでなく、候補順位の加点区分にも影響する。変化技を完全にシミュレートしないという制約とは別に、現在出す根拠の分類が誤っている。

修正方針：生成元から効果対象・変化する能力・増減を保持し、上昇と下降を区別して説明・評価する。生成JSONの直接編集ではなく生成スクリプトから修正する。
